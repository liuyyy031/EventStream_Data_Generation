# Hydrology：降雨产流、河道传播与测站响应

这是水文领域的第一个可执行子域，范围是一次短时过程内的降雨、降雨损失、直接径流、树状河道汇合及测站报告。
它复用公共调度器、时间模型、验证器、文本对齐、QA 和语义矫正，不引用其它领域的执行代码。
不是完整水文模拟器，不覆盖地下水、融雪、潮汐、库坝调度或洪水淹没范围；阈值越过也不能写成“已经发生洪灾”。

## 节点含义与图约束

四种节点分别是子流域 `catchment`、河段 `reach`、测站 `gauge` 和管理单位 `management_unit`。
千节点默认包含 300 个子流域、400 个河段、250 个测站及 50 个单位。总节点预算不是测站数，也不是必须发生事件的节点数。

子流域各排水到一个河段；除出口外，各河段只流向一个下游河段，最多接收三条支流，没有循环。
测站观察一个河段并报告给一个单位。当前河道是一棵随机生成的汇流树；类型绑定不自动产生其它跨类型边，不套用空间格网或全节点随机连通。
不同上下文随机改变支流连接、物理参数；合成树只约束可传播路径，不代表已测绘的真实流域。
千节点图有 1199 条背景关系，不需要幅值矩阵。水文中采用树状流向是本子域的结构约束，不是所有领域都必须用树。

子流域属性包括面积（km²）、初始损失（mm）、恒定损失率（mm/h）及响应滞后（s）。
河段包括长度（m）、洪水波传播速度（m/s）、参考基流与合成流量阈值（m³/s）。波速不是水粒子流速。
基流采用每河段 .15 m³/s 的局地参考贡献，并在下游累加上游贡献；这是合成基准，不是实际流域基流估计。

## 产流量与发生时间联合确定

降雨开始事件抽取恒定雨强 `i` 和有限时长 `T`，作为这个离线合成过程的已知标记，不是从文本猜测未来天气。
采用全透水子流域的初始与恒定损失模型。剩余初始损失为 `D`，恒定损失率为 `f`，面积为 `A`。
当 `i>0` 时，填满初始损失需要：

\[
t_{fill}=3600D/i.
\]

只有 `i>f` 且 `T>t_fill` 才产生正直接径流；否则输出 `runoff.not_generated`，不强制后续传播。
产生径流时：

\[
W=T-t_{fill},\quad
q=(i-f)A/3.6,\quad
V=qW,\quad
P_{excess}=V/(1000A).
\]

这里 `W` 为秒、`q` 为 m³/s、`V` 为 m³、降雨深度 `P=iT/3600` 为 mm。
输出总损失 `P-P_excess`，因此降雨水量可复算为径流水量加损失水量。
子流域响应使用纯平移 `τ_c`：径流到达排水河段的时间是 `t_rain+t_fill+τ_c`，持续 `W` 秒；结束时间不是简单的降雨结束时间。
因此时间与事件类型/事件标记受同一套损失及传播规则约束，不是先随便选事件再独立生成 Δt。

例如 `i=20 mm/h, T=7200 s, D=5 mm, f=3 mm/h, A=1 km², τ_c=600 s`：
填满初始损失需 900 s，径流开始于降雨后 1500 s，持续 6300 s，流量约 4.722 m³/s，径流水量 29750 m³。
总雨量 40 mm，其中直接径流 29.75 mm、损失 10.25 mm；径流结束于降雨后 7800 s，晚于降雨结束的 7200 s。

当前是**矩形降雨经损失与纯滞后得到矩形直接径流**，没有模拟逐渐涨落的完整水文过程线。
这是公开简化假设，不是声称真实洪峰都呈矩形，也不是调用 HEC-HMS 软件得出的结果。

## 河段传播与支流汇合

对上游河段 r，传播滞后为：

\[
\tau_r=L_r/c_r,\qquad q_{down}(t)=q_{up}(t-\tau_r).
\]

使用 Lag routing 的纯平移假设：不衰减、不展宽、不增加或丢失水量。波形首端和尾端平移同样的时间。
每个河段的事件和测站流量指该河段入口的代表断面，下一河段入口通过上一个河段的滞后获得流量；不是宣称整段河道瞬时达到相同状态。
每个实际产流事件拥有独立 `pulse_id`；沿真实相邻下游边逐段传播，每个河段仅到达一次并有唯一结束候选。
模拟窗口内尚未完成的尾端或下游到达应右删失，不能删掉后把过程写成已经结束。

河段当前总流量为：

\[
Q_r(t)=Q_{base,r}+\sum_{p\in Active_r(t)}q_p.
\]

只累加已到达且尚未结束的正流量贡献。两个上游连通但时间不重叠时，不能声称“共同造成”这次流量变化。
越过阈值时保存实际贡献列表、各自流量、总流量和阈值；一项贡献使用单父规则，多项贡献使用 `all_of` 规则。
这些父边标记为 `derivation`，表示数值叠加的推导依据，**不是声称每项都是必要因果原因或识别出了最小充分原因集**。
降至阈值以内时记录结束贡献及之前的超阈值事件，不能把其它历史支流任意加入父事件。
同一时间先处理物理边界，再处理阈值推导与采样；脉冲区间采用 `[到达,结束)`，同一时刻结束和开始不算持续重叠。
流量 epoch 发生改变后，旧阈值候选取消，并按更新后的真实活动集合重新判断。

验证体积守恒应比较一个源脉冲与出口通过的水量，不应将所有河段的水量简单相加：同一份水会经过多条河段，被重复计入。

## 监测与预警不等于物理事件

本版测站是阈值变化触发的采样，不是固定间隔、带观测噪声的完整监测序列。
采样记录流量、阈值、是否超阈值、采样时间和序号；经过通信延迟发布报告，报告严格保留采样快照。
报告晚于水流退去仍可以报告此前高流量，不能按报告发布时的物理状态改写原标本数据。

乱序到达的较旧报告仍保存，但标记 `stale_report=true`，不能覆盖更新的已送达采样，也不能启动新预警。
管理单位依据最新已送达报告发出或撤销合成流量预警。响应候选若被更新的报告取代则取消。
`warning_basis` 明确为“最新送达测站报告”，不保证预警发布时当前真实流量仍高，也不证明发生淹没。
物理真值、采样观测、报告通信、行政工作流分别标记关系语义。

## 情景、时间先验与范围

- `isolated_storm`：一个子流域的一场降雨，可不产流、可传播但不越阈值。
- `tributary_confluence`：两条确实汇入同一河段的不同支流各有一个降雨根候选；到达可能重叠也可能不重叠，不保证双父事件必然产生。
- `repeated_storms`：同一子流域两个连续降雨过程，雨间有正等待时间，保留已经消耗的初始损失。复发边标记 `statistical_influence`，是情景的天气序列先验，不声称上一场雨物理造成下一场雨。

降雨结束时更新 `D_next=max(0,D-P)`；短时连续降雨之间不模拟蒸散恢复，因此不能用它生成长期连续气候/地下水序列。
默认雨强均匀先验 4～32 mm/h、时长 1800～7200 s、初始损失 2～12 mm、恒定损失率 2～12 mm/h。
面积 .3～2 km²、子流域响应滞后 300～1800 s、河段长度 300～1500 m、固定波速 .8～2 m/s；这些数值均是合成先验，不是文献拟合参数。
源候选到达为指数等待（1/小时）；雨间等待、通信、响应、日志入库为正对数正态等待，中位数分别 1800、72、30、5 s，对数标准差分别 .4、.5、.4、.4。
物理 Δt 则按填满初始损失、源脉冲宽度、逐边传播公式计算，不用同一独立随机分布替代所有时间关系。
24 小时完整观察窗独立于首末事件跨度；2048 事件上限是行政保护而非自然长度。时间轴显示小时，内部仍保留秒；`_seconds` 字段仍以秒计。

## 依据与限制

[HEC-HMS 初始与恒定损失模型](https://www.hec.usace.army.mil/confluence/hmsdocs/hmstrm/canopy-surface-infiltration-and-runoff-volume/infiltration/initial-and-constant-loss-model) 提供“初始损失填满前不产流、之后按恒定损失率扣减”的依据，适用于事件尺度，不能自行恢复干燥状态。
[HEC-HMS Lag model](https://www.hec.usace.army.mil/confluence/hmsdocs/hmstrm/channel-flow/lag-model) 提供纯时间平移、不衰减的路由形式，其适用范围本身有限。
本实现借用这两类既有方法的简化形式，并自行组织事件表示、观测工作流和一致性验证；不是 HEC-HMS 全模型复现。

没有河道蓄水衰减、扩散、变波速、回水、动态水位率定、库坝、融雪、蒸散、地下水及淹没求解；基流和阈值也尚未实测拟合。
本阶段能验证的是生成机制内的水量/时间约束一致、关系可追溯、文本可对齐，不声称统计真实或完整水文领域覆盖。
服务器上传及测试见 [测试协议](../../docs/HYDROLOGY_TEST_PROTOCOL.md)。
