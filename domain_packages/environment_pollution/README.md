# Environment & Pollution：河网水质污染脉冲

本包是 Environment & Pollution 的**首个可运行子范围**：淡水河段上的单次溶解性污染负荷、顺流输送、监测告警和取水口响应。它不把空气扩散、土壤迁移、生态暴露或多介质化学反应合并成一种传播公式。目标是机制自洽的事件流，而不是复现某条真实河流。

## 节点含义和图

| 节点 | 含义 | 静态关系 |
|---|---|---|
| reach | 一段河道；含长度、参考流量、流速、损失率 | 除出口段外，每段恰有一条指向下游的 `reach_flows_to_reach`；允许多支流汇入 |
| outfall | 工业排放口或污水处理出水口 | 恰好排入一段河道 |
| catchment | 有面积和径流系数的汇水区 | 恰好汇入一段河道 |
| monitor | 一处水质监测点 | 监测一段河道，具有合成告警阈值 |
| intake | 一处取水口 | 使用一段河道，并接收该段监测点的报告 |

默认 1000 个节点对应 333 段河道、200 个排放口、100 个汇水区、200 个监测点和 167 个取水口。河道是有向无环汇流树，不是道路网格；共有约 1000 条稀疏类型关系，不构造节点平方矩阵。每次 episode 选一个配有监测点和取水口的上游入口，这是**有条件的可观测案例采样**，不是对所有河段的均匀环境发生率估计。图上能流到下游只说明传播可行，真正的父事件必须是已发生、质量通量仍高于报告下限的那次污染脉冲。

## 三条机制链

1. `industrial_spill`：工业排放口突发溶解性负荷 → 进入接收河段 → 沿实际下游链逐段传播 → 有限排放结束 → 脉冲尾缘依次清除。
2. `wastewater_bypass`：处理设施旁路开始 → 经设备响应延迟形成出水负荷 → 同一河段传播、监测和有限负荷结束流程。旁路结束标为合成的 `bypass_repaired`，不表示真实工程维修细节已建模。
3. `storm_runoff`：降雨开始 → 经汇水响应延迟形成面源径流负荷 → 从汇入河段向下游传播。

监测点只在该段估算增量浓度达到**合成监测阈值**时发出延迟告警；取水口收到告警后按规则关闭。污染尾缘经过该段且此前确实发过告警，监测点才报告正常；取水口只有在关闭且收到正常报告后重新打开。样本可能在观察窗结束时仍有未到达、未清除或未恢复的候选；保留右删失，不伪造完整结局。`workflow.settled` 仅表示本次物理脉冲已通过出口或低于报告下限且尾缘已清除，不要求所有较晚的监测/操作记录都已经入库。

## 数值与时间合同

对于本包定义的合成溶解性污染物，以下公式按单位计算：

\[
Q_r = 0.35\,N_{\mathrm{upstream},r}\quad (\mathrm{m^3/s}),\qquad
Q_{\mathrm{runoff}}=I_{\mathrm{mm/h}}A_{\mathrm{km^2}}c/3.6.
\]

\[
F_{\mathrm{source}}=Q_{\mathrm{source}}C_{\mathrm{source}}/1000\quad(\mathrm{kg/s}),\qquad
\Delta t_{r\to d}=L_r/v_r.
\]

\[
F_d=F_r e^{-k_r\Delta t_{r\to d}},\qquad
\Delta C_r=1000F_r/(Q_r+Q_{\mathrm{source}})\quad(\mathrm{mg/L}).
\]

工业排放量也按接收段参考流量和抽样的合成浓度增量计算，确保单位自洽。上式中的 `0.35 m³/s`、`k=0.001/s`、源强、监测阈值 `1 mg/L` 和传播报告下限 `0.05 mg/L` 都是公开的**合成先验/策略值**，不是环境标准或实测拟合。这里只追踪一次脉冲；固定参考流量加源水量，不求解水动力方程。汇流节点没有同时来自多个污染源的负荷相加问题，因为单次 episode 只有一个源。

| 时间过程 | 模型和作用 |
|---|---|
| 起始事件 | 指数等待，默认 0.05/s；只为选定的一次案例计时 |
| 旁路形成负荷、降雨形成径流 | 各自对数正态响应延迟，中位数基准 3s / 10s |
| 有限负荷持续 | 对数正态，中位数基准 20s；尾缘由负荷结束时间决定 |
| 河段传播 | 按上一河段 `L/v` 确定性延迟，不是固定长度时间桶 |
| 河段清除 | `t_loading_end + 累计行程时间`；必须同时有实际到达和负荷结束两父事件 |
| 监测报告 | 从到达/清除事实经对数正态报告延迟，中位数基准 1.2s |
| 取水口关/开 | 收到相应监测报告后 2s 策略延迟；不能从不可见的河道状态直接行动 |

物理到达和清除的 `observed_at` 是离线合成真值中的发生时刻，**不表示监测点当时已知道**。监测告警是后续独立事件；取水口只能依其已收到的报告行动。`recorded_at` 是再往后的日志入库时刻。输出文本逐事件、逐关系对齐结构证据，QA/训练视图复用公共导出；LLM Judge 可以审核并驳回，语义矫正不能改动结构或答案。

## 依据与边界

美国 EPA 的 [WASP 水质模型说明](https://www.epa.gov/hydrowq/water-quality-analysis-simulation-program-wasp)明确区分点源/面源负荷、平流、弥散和边界交换；[WASP 模型文档](https://www.epa.gov/hydrowq/wasp-model-documentation)列有水输送的控制方程。这里借鉴的是**过程分解与质量守恒方向**，没有实现 WASP。本包省略弥散、沉降、再悬浮、反应网络、季节流量、潮汐、空气/土壤扩散、真实法规阈值和多源叠加，也不声称统计分布真实。
