# Agriculture：首个可执行农业子域

本轮实现的是**既有作物群体的根区水分、热量积累、监测和灌溉管理**，不是整个农业的完备模拟器。
继续使用公共调度、稀疏类型图、观察延迟、语义审核/矫正、QA、训练导出及共享前缀续生成组件；没有把交通专用逻辑搬进农业。

## 节点与静态联系

| 节点 | 含义与关键属性 |
| --- | --- |
| `field` | 农田；面积 ha、田间持水量/萎蔫点 m³/m³、固定根深 m、允许耗水比例 |
| `crop_cohort` | 已建立的虚构一年生作物群体；温度界限、积温阈值和分阶段作物系数 |
| `soil_water_sensor` | 对根区水分的理想估计设备；阈值变化时采样，不等于现实中一个点位的原始探头 |
| `irrigator` | 独立灌溉设备；流量 m³/s 与施用效率 |
| `supply_unit` | 可在线/失效的共享供水单元；额定能力支持所有接入设备同时运行 |
| `weather_zone` | 恒定平均温度与参考蒸散输入所属区；不意味着所有区内田块同时降雨 |

五种边分别是作物所在田块、传感器观测田块、设备服务田块、设备接入供水、水田所属天气区。
前三者是一对一绑定；供水与天气可以共享。不添加无语义随机田块边，不要求全图连通。
单个田块的有效降雨是局部外源输入，不自动扩展到整个天气区。

1000 个节点默认包含 242 田块、242 作物群体、242 传感器、242 灌溉设备、20 供水单元和 12 天气区，形成 1210 条功能边。
这些是背景实体总数，不是 1000 块田，也不承诺每个节点在一个 episode 中都产生事件。
一次情景选取一个田块，或者同一供水下的两个田块；这是可审计的局部片段设计，不是全区域农业活动发生率模型。

## 三类情景

- `rainfed_drydown`：雨养田块蒸散耗水，允许一次独立有效降雨候选；无灌溉干预。
- `irrigation_response`：耗水越过阈值，采样、报告、请求灌溉；有限流量补水后再次耗水，形成多轮事件。
- `shared_supply_interruption`：两个田块共享供水，增加一次外源故障及维修；视故障发生时状态，可以延期、中断，也可以不影响正在进行的灌溉。

根事件数由情景设计决定。指数模型只决定这些候选的到达时刻，**不是在整个窗口内持续生成的完整降雨/故障泊松过程**。
默认观察窗为 45 day。没有强制恢复或强制中断；窗外候选右删失，旧状态候选取消。

## 时间来自什么依据

### 水分：阈值时间由水量变化推导

采用 [FAO-56 第 8 章](https://www.fao.org/4/x0490e/x0490e0e.htm) 的根区水分和单系数近似：

```text
TAW = 1000 (θFC − θWP) Zr                 # mm
RAW = p TAW                              # mm
Ks = 1                                  # Dr ≤ RAW
Ks = (TAW − Dr)/(TAW − RAW)               # RAW < Dr ≤ TAW
r = Kc ET0                              # 潜在作物蒸散 mm/day
J = η Q × 86400 / (10 Aha)               # 灌溉净入水 mm/day
dDr/d(day) = r Ks(Dr) − J
```

`Dr` 是相对田间持水量的亏缺，不是土壤总含水量。有效雨使亏缺减少，超出根区容纳量的输入计入深层渗漏。
每段恒定系数下，`Dr ≤ RAW` 为线性解，水分限制段为指数解；直接求第一次越过 RAW 的时间，不按固定时间格切分。
本实现固定根深、无地下水补给；单系数近似不适合裸土蒸发占主导的情形，未实现双作物系数法。

每条田块事件保留累计账本，并回放检查：

```text
Dr(t) = Dr(0) + cumulative_ET − cumulative_net_irrigation
        − cumulative_effective_rain + cumulative_deep_percolation
```

状态改变时只替换未来预测，不清空已经积累的水量。`readily_available.exhausted` 是 RAW 边界，不是作物死亡或减产结论；刚到边界时 Ks 仍可等于 1。
`effective_rain.received` 的输入是已经到达根区的有效水深，不是总降雨量；不声称模拟了降雨入渗、地表径流或洪涝。

### 热量：积温与灌溉时钟分离

温度积累参考已有的热时间方法，可见 [FAO 小麦生理资料](https://www.fao.org/4/y4011e/y4011e06.htm)；这里不采用其中任何具体品种的拟合参数。

```text
g = max(0, min(Tmean, Tupper) − Tbase)     # degree-day/day
GDD(t) = integral(g × d(day))
Δt_days = (GDD_target − GDD_current) / g  # g > 0
```

达到阈值后切换当前阶段 Kc，同时重新推导水分越界时间。温度低于基温时不强制推进。
80/240/480 degree-day、8/30°C 和四个 Kc 值都是**虚构作物的合成参数**，不是 FAO 给出的通用农业常数。
事件和文本明确写为 `thermal_milestone` / `thermal_proxy`；不把积温达标声称为实测开花、成熟、收获或产量。

### 灌溉：剂量、设备流量与时长约束

```text
gross_depth_mm = (Dr_current − target_depletion) / η
gross_volume_m3 = gross_depth_mm × 10 × Aha
duration_seconds = gross_volume_m3 / Q
```

启动时按当前亏缺重新计算剂量，补水在该时段连续发生，不在结束事件瞬间一次性加水。
期间仍然蒸散，因此结束时不保证精确到达计划目标；该假设写入事件 `dose_policy`。
供水中断后立即停止入水，只记录已输送的部分，取消旧结束候选；维修后如请求仍有效，再按当前亏缺重新启动。
已恢复水分且不再灌溉时会释放过期请求，避免阻塞下一轮。

### 随机等待与确定性时间的边界

| 时间 | 当前模型 | 参数性质 |
| --- | --- | --- |
| 作物建群、有效雨、供水故障候选 | 指数到达 | 人工合成先验，非真实发生率估计 |
| 水分越界、积温达标 | 分段解析状态方程的剩余时间 | 已有物理/生理建模思想的受限实现 |
| 灌溉完成 | 剂量/设备流量 | 设备单位约束 |
| 维修、通信、控制、执行及日志摄入 | 条件对数正态组件，当前无协变量 | 人工合成延迟先验 |
| 故障中断、阈值触发采样/延期 | 同时刻动作，阶段优先级排序 | 显式离散事件规则 |

方程的采用有文献依据，选择何种情景、节点绑定、参数范围、调度与文本投影是本项目的工程设计，不能据此声称统计真实性已被证明。

## 事件联系与文本

共有 14 种具体事件、15 个机制。功能连边不等于事件父子关系。
水分越界是当前水量状态的 `derivation`；采样是 `observation`；样本上报是 `communication`；控制/维修分别是工作流或状态转移。
水分方程段的父事件是段起点，不表示此前历史对水分不再有影响：累计水量仍保留。

多父机制要求实际事件：

- 中断 = 实际灌溉启动 + 对应供水故障。
- 延期 = 有效请求 + 对应供水故障。
- 重启 = 仍需灌溉的请求 + 对应供水恢复。

报告携带原采样时间、水分与序号，也携带报告时的当前状态。旧样本不会被改写成当前读数。
乱序报告保留，但不能覆盖较新的观测，也不能据此执行过期请求；执行前再次检查当前水分与供水。
默认文本来自结构化事实的确定性投影，保留实体角色、时间、主要物理量和关系类别。公共 LLM 仅审核/矫正表达，不决定水量、事件、时间或 QA 标签。

## 六项公共约束在本领域的落点

1. 续生成保留共享前缀中的亏缺、累计水量、积温、供水和请求状态；只对允许的未来随机时钟做条件续生成。
2. 输出时间单位是 day，内部秒制；水量 mm、流量 m³/s、温度 °C、积温 degree-day 显式转换。
3. 观察时长独立于事件个数；允许短窗零事件，单独记录行政截断，不保证每条链完整结束。
4. 五层功能关系不用人工社区；不为了连通性引入无意义的田块联系。
5. 窗口起止与首末事件跨度分开；本域小片段不能用于推断全域农业发生率。
6. 当前事件取决于累计水分和热量、阶段、历史样本序号、请求与设备状态，不只取决于前一个事件类型。

## 验证与范围边界

确定性验收回放类型绑定、父事件、累计水量、积温目标、灌溉剂量/时长、部分交付及采样快照。
共享前缀分支不是因果反事实；同组分支应放在同一数据划分。
测试与上传命令见 [服务器验收协议](../../docs/AGRICULTURE_TEST_PROTOCOL.md)。

尚未覆盖病虫害、养分、作物竞争、动态根深、冻害/热害、真实噪声传感器、分层土壤、洪涝、收获与产量，以及有限水库/配水队列。
天气在一个 episode 内恒定，只有一次有效雨候选；模型只是受约束的农业事件流子域，不代表所有农业事件规律。
通过程序验收不等于真实农场分布已校准，也不等于 LLM 已经学会理解这些数据。
