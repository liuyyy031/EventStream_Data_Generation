# 通用事件序列数据生成核心（开发版）

## 当前范围

这一开发版保留旧交通实现作为可复现基线，在独立目录中实现领域中立的候选事件调度核心。交通领域已经接入事故传播、天气扰动、计划封路和天气—事故复合机制；医学和分布式系统领域目前只建立协议结构，不生成可用于真实性声明的数据。

当前科研目标是生成可供后续 LLM 事件序列理解使用的多领域数据；现阶段只解决数据生成与验证，不把后续 LLM 训练效果作为本阶段通过条件。交通是当前第一个优先完成的领域类别，但不是通用核心的默认语义，也不被定义为论文中的示例。后续领域应复用同一合同和运行时，而不是复制交通机制或替换交通字段名称。

通用核心不认识“道路”“患者”或“服务”等领域词。每个领域包负责提供实体类型、上下文关系、事件类型、机制规则、参数和观测过程。上下文拓扑只表达哪些实体可能交互，不自动产生事件父子关系；事件父子关系必须由一次实际执行的机制规则建立。

## 通用不规则上下文图

上下文不再由交通专用的走廊、规则网格、枢纽或随机连通链生成，而统一表示为稀疏、带类型、可分层并可带有效时间的关系图：

`G_C(t) = (V, E(t), T_V, T_E, X_V, X_E)`。

通用引擎目前提供三种关系层算子：

- `constrained_degree_weighted_block`：用节点权重和社区偏置表达度异质性，再施加最大度与连通性硬约束；
- `typed_bipartite`：表达设备—患者、服务—主机等跨类型关系；
- `directed_acyclic`：表达有序工作流或不可回环的依赖层。

这不是用一个固定随机图分布强行覆盖所有领域。相同的是稀疏生成运行时、类型检查、统计输出和硬约束执行；不同领域通过关系层规范选择算子并配置允许的源/目标类型、连通性、方向、环路、社区、度分布、枢纽和时间有效性。多元关系通过把就诊、工作流或会话等关系实例提升为实体来表达，不把多个参与者强制展开成无意义的两两连边。

交通领域现在也使用该通用引擎，只要求道路关系层弱连通；节点不再需要 `x/y` 坐标。医学和分布式系统不要求全局连通，并分别声明跨类型监测/归属层和调用/部署层。所有生成算法使用邻接表和边采样，不创建 `N×N` 稠密矩阵。

每个上下文独立采样社区数、期望度、度异质程度、枢纽比例和社区内连接偏置，因此多张图的结构参数并不相同。输出的 `contexts.jsonl` 和整批质量报告保存实际采样配置与观测统计，包括边数、平均/最大出度、连通分量和社区内边比例。

三份领域目录现在都包含可执行的 `domain_spec.json`。通用加载器会检查实体类型、关系类型、关系端点类型、图算子和结构参数，再把关系层编译成同一个稀疏生成接口。交通包只在运行时覆盖其已声明关系层的采样参数，并注册道路关系属性构造器；医学和分布式系统规格目前只可编译结构，不含未经依据确认的事件概率。JSON 规格不能越权改变关系端点类型，也不能用一个未声明的关系层覆盖领域合同。

上下文关系通过稀疏索引按实体、关系类型、方向和查询时刻读取。若一条边带有 `valid_from_offset_seconds` / `valid_to_offset_seconds`，规则只能在有效区间内看到它，因此动态部署关系、监测绑定或临时连接不会被错误地当成整段观察窗都有效。

这里采用的数学思想不是凭空创造：度修正随机块模型用于同时表达社区与宽度分布；给定期望度的随机图说明度序列和连通分量必须显式控制；时变网络研究说明静态聚合图不能替代瞬时关系；异构信息网络研究强调节点类型和边类型携带不可省略的语义。参考：

- Karrer & Newman, [Stochastic blockmodels and community structure in networks](https://arxiv.org/abs/1008.3926)；
- Chung & Lu, [Connected Components in Random Graphs with Given Expected Degree Sequences](https://doi.org/10.1007/PL00012580)；
- Perra et al., [Activity driven modeling of time varying networks](https://arxiv.org/abs/1203.5351)；
- Sun & Han, [Mining Heterogeneous Information Networks](https://www.kdd.org/exploration_files/V14-02-03-Sun.pdf)。

`constrained_degree_weighted_block` 不是对原始度修正随机块模型的逐式复现，而是受其启发的工程采样器：基础抽样使用节点权重和社区偏置，随后加入连通骨架、最大度、类型约束和拒绝采样。论文中应把它表述为“基于度修正块模型思想的受约束变体”，而不能写成直接使用标准 DC-SBM。本工程其余自定义内容包括统一接口、关系层配置、确定性种子、稀疏实现、硬约束验证和输出证据合同。未使用领域参考数据拟合时，结构参数仍标记为合成先验。

## 核心时间语义

事件规则先产生候选机制，候选机制引用一个时间模型。静态时间模型在激活时采样一次；时变风险模型保存指数随机阈值并累计风险，状态更新不会无条件重置时钟。所有候选进入确定性优先队列，执行前再次验证前置条件。

当前时间模型家族包括：

- 确定性延迟与日程时间；
- 条件对数正态延迟 `log(Δt) = β0 + βᵀx + σε`；
- 条件 Gamma 延迟 `Δt ~ Gamma(shape, rate=exp(β0+βᵀx))`；
- 条件 Weibull 延迟 `S(Δt|x)=exp(-(Δt/exp(β0+βᵀx))^shape)`；
- 指数到达间隔 `Δt ~ Exponential(λ)`；
- 分段常数风险 `λ(t|x) = λ0 exp(βᵀx)`；
- 经验延迟重采样；
- 指数退避策略。

这些是标准数学模型家族；“候选生命周期、统一接口、证据字段和确定性调度”是本工程的组合设计。交通包里的数值参数不是从真实数据估计出来的，统一标为合成先验。每条关系保存实际使用的时间模型引用和采样证据。

Δt 只有同时满足以下约束才会被接受：候选已满足父事件条件；时间不早于全部实际父事件；传播类机制不早于物理最短通行时间；状态变化后保留已经累计的风险；相互竞争的候选在执行前重新验证；越过观察窗的候选被右删失而不是当作未发生；发生、观测和记录时钟相互分离。

候选终态包括：

- `fired`
- `cancelled`
- `superseded`
- `right_censored`

事件时间区分实际发生、观测和记录；事件关系同时保存时间锚点、关系滞后和时间模型引用。

多父事件只记录实际参与该机制的父事件。`all_of` 的激活时间取实际父事件中最晚发生者；`any_of` 只记录真正触发的一个父事件；`k_of_n` 必须同时记录候选池大小、阈值 k 和实际满足的 k 个父事件；有上下文连边但未参与机制的事件不会被写成父事件。

## 时间、类型与实体的联合生成

实现不再把“下一事件是什么”和“多久发生”写成两个独立抽样器。历史 `H_t` 和上下文 `C_t` 先激活一组具体候选 `R(t)`；一个候选同时绑定机制、目标事件类型、参与实体、父事件和时间模型。对可连续计时的候选 `i`，时间模型提供原因特异风险 `λ_i(t|H_t,C_t)`。总风险与共同生存概率为：

`Λ(t)=Σ_{i∈R(t)} λ_i(t)`，

`S(t)=exp(-∫Λ(u)du)`。

因此候选 `i` 在时间 `t` 成为下一事件的联合密度是 `λ_i(t)S(t)`。类型和实体概率不是另外指定的固定枚举概率，而是从同一个风险集合聚合出来：

`P(type=k | t,H_t,C_t)=Σ_{i:type(i)=k}λ_i(t)/Λ(t)`，

`P(entity=z | t,type=k,H_t,C_t)=Σ_{i:type(i)=k,entity(i)=z}λ_i(t)/Σ_{j:type(j)=k}λ_j(t)`。

这与先分别采样多个相互独立的候选时钟、再取最早到期者在数学上等价，但风险集合表达能明确输出 `g(time|history)`、`h(entity|time,history)` 和 `f(type|time,entity,history)` 所依赖的是同一组条件风险，而不是错误地假设时间、类型和实体相互独立。顶层分解受 [arXiv:2103.04647](https://arxiv.org/abs/2103.04647) 的时空标记点过程分解启发；“候选机制合同、风险集合 JSON、实体/类型风险聚合与确定性校验”是本工程的实现设计，不应写成该论文的原样算法。

日程、固定超时等确定性时间是点质量，不存在普通连续密度；经验离散时钟和策略时钟也不会被伪装成连续风险。若它们到期，调度器按公开的阶段优先级与领域优先级处理，并在证据中标记 `deterministic_atom_priority` 或离散/策略时钟模式。这样既保持统一调度，又不滥用连续时间点过程公式。

每次事件发生前都会保存一个 `risk_set`：所有当时仍有效的候选、时间模型引用、已存活概率、瞬时风险、归一化候选概率、类型条件概率、实体条件概率及调度优先级。发生后，事件和候选都反向保存 `risk_set_id`。因此输出能够回答“为什么是这个时间、这个类型、这些实体”，同时保留未发生候选用于右删失和负例构造。

父事件归因与风险竞争分开处理。无父候选标记为独立背景事件；单父候选把实际规则父事件记为归因权重 1，这个数只表示“该生成规则唯一引用了它”，不是因果效应量；`all_of`、`k_of_n` 等显式联合规则记录全部实际父事件，但在没有可识别的贡献模型时不虚构每个父事件的概率权重。论文中的历史贡献或事件谱思想可作为以后加入 `contribution_weighted_history` 的依据，当前版本只声明已经由机制规则执行并可验证的父子关系。

候选与事件关系还可携带结构化 `context_evidence`：规则实际使用的上下文关系 ID、涉及的实体、检查时刻，以及状态谓词的期望值、实际值与判断结果。以交通传播为例，证据同时记录“哪条下游关系在该时刻有效”“源路段当时为拥堵”“目标路段当时为正常”。确定性验证会检查 ID 存在、关系端点完整、触发时边仍有效、已触发规则的谓词全部通过，并确认事件关系原样保留其生成候选的证据。这仍然只是规则前置条件证据；因果父子关系必须由实际执行的事件机制另外声明。

## 开放类型体系

`event_type_id` 是带命名空间的层次类型标识，不是封闭的 Python 枚举。每次输出包含 `domain_catalog.json`，列出本批次允许的实体类型、事件类型、必需属性、关系类型和机制。新增叶子类型只需扩展领域目录与领域规则，不修改通用事件记录结构；未注册类型或缺失必需属性会被确定性验证拒绝。

## 参数真实性边界

交通包当前参数均标记为透明合成先验，只用于验证结构、调度、关系和时间证据链。没有参考数据拟合和独立留出验证时，不声称统计真实性。

当前交通机制族用于证明架构能表达不同逻辑，而不只是同一种拥堵链：

- 事故 → 拥堵 → 下游传播/恢复；
- 大雨 → 天气诱发拥堵 → 传播/恢复；
- 大雨 → 天气条件下事故 → 天气与事故共同导致拥堵；
- 计划封路 → 到期开放。

其中复合机制会为同一目标事件写出两个父关系，并共享同一个 `mechanism_group_id`；这两个父事件来自实际执行的联合规则，不来自“节点连通即因果”的推断。

天气与事故或拥堵之间若只有统计资料而没有明确链接、业务规则或更强因果证据，关系类别使用 `statistical_influence`，不自动写成 `causal`。天气—事故联合产生拥堵使用独立机制 ID，避免让一个单父机制名称承载双父规则。参数拟合不能自动把统计影响升级为因果关系。

## 可选的参考数据与参数校准合同

当前阶段的通过目标是结构有效、时间—类型—实体联合选择自洽、事件链可追溯和文本可对齐，并不要求生成分布复刻某个真实交通数据集。下述参考数据接口只在以后需要声称经验统计一致性、或需要用观测数据替换透明合成先验时启用；它不是运行通用生成器的前置条件。

真实校准从规范化参考数据开始，而不是用当前合成输出反向拟合当前生成器。参考数据目录至少包含：

- `reference_manifest.json`：领域、数据集身份、版本和划分策略；
- `reference_windows.jsonl`：连续时间观察窗、上下文和 train/validation/holdout 划分；
- `reference_events.jsonl`：来源记录 ID、事件类型、发生/观测/记录时间、参与实体、明确父记录和 trace ID；
- 可选 `reference_entities.jsonl` 与 `reference_context_relations.jsonl`。

加载器检查时间顺序、观察窗边界、实体引用、明确父事件必须存在且不得晚于子事件，以及按上下文划分时同一上下文不得跨训练与留出集。默认拒绝同一上下文中的重叠观察窗，防止重复计算暴露时间。数据指纹覆盖全部规范化记录和来源元数据。

机制通过领域目录内的 `mechanism_specs.json` 声明。通用字段包括源/目标事件类型、父组合方式、所需上下文关系、时间模型家族、生成时模型引用、协变量、关系语义、证据策略、拟合器和参数状态。交通与医学首批机制已经声明；分布式系统目前保留合法空目录。医学包用于机制一致、可审计的合成住院监测工作流，不声称诊断、处方、疗效或经验统计真实性；通用核心中仍然没有领域分支。

第一项可执行拟合器是无协变量常数强度的最大似然估计：

`lambda_hat = observed_event_count / total_exposure_seconds`。

训练中零事件的观察窗仍贡献完整暴露时间；留出集只做独立诊断，不进入参数估计。输出 `calibration-bundle-v1`，保存参数、不确定性、训练范围、拟合指标、留出指标、数据指纹和观察指纹。产物状态固定为 `empirically_estimated_pending_domain_acceptance`，不会仅因程序执行成功就自动进入生成配置。

带协变量的传播、恢复和条件延迟尚未选择拟合器，因为它们需要先确认参考数据能否构造合格风险集、竞争事件和删失记录。在此之前继续保留 `pending_reference_data`，不得用合成输出冒充经验校准。

通用校准入口为：

```bash
python data_generation/run_parameter_calibration.py \
  --mechanism-spec <domain-package>/mechanism_specs.json \
  --mechanism-id <namespaced-mechanism-id> \
  --reference-dir <normalized-reference-directory> \
  --output <calibration-bundle.json>
```

## 当前入口

```bash
python data_generation/run_data_generation.py \
  --domain transportation \
  --episode-count 10 \
  --nodes-per-context 1000 \
  --output-dir data_generation/output_multidomain_transportation
```

医学领域使用同一入口与输出协议，只替换领域包：

```bash
python data_generation/run_data_generation.py \
  --domain healthcare \
  --episode-count 20 \
  --nodes-per-context 1000 \
  --seed 20260916 \
  --output-dir data_generation/output_healthcare_20
```

可用 `--scenario-family` 固定某个场景做单元检查，或用配置文件中的 `scenario_weights` 生成混合批次；`--max-events-per-episode` 可覆盖行政上限。若达到该上限，整批质量门会失败并报告 `administratively_truncated_episode_count`，不会把不完整 episode 当作合格输出。

本机开发默认使用 `--judge-mode none`，不会访问外部服务。上传服务器后若启用 LLM 语义审查，必须显式指定模型：

```bash
python data_generation/run_data_generation.py \
  --episode-count 20 \
  --nodes-per-context 1000 \
  --seed 20260914 \
  --judge-mode llm \
  --judge-model deepseek-v4-flash \
  --judge-workers 4 \
  --semantic-correction-mode llm \
  --semantic-correction-max-rounds 2 \
  --output-dir data_generation/output_llm_checked
```

密钥与默认服务地址从服务器 `.env` 自动读取，不需要重复 `export`。

协议解析失败会在同一次 LLM 审查内部重试，不会被误算成语义拒绝；连续协议失败会令整批质量门失败并停止后续生成重试。Judge 对拒绝结果同时给出 `issue_scope`：`text` 表示结构化 episode 本身成立、仅文本表达需要修改；`structure` 表示事件、关系、时间、实体、候选或风险集存在结构问题；`mixed` 表示两类问题同时存在。只有 `text` 会进入语义矫正器，在同一个 episode 上依据 Judge 反馈重写句子并再次接受确定性对齐和 Judge 审查；事件 ID、时间、参与实体、父事件、关系类别、候选状态和风险集始终冻结。`structure`、`mixed`，以及文本达到最大矫正轮数后仍被拒绝的 episode，才会更换 seed 重新生成，最多执行 `--judge-max-generation-attempts` 次。Judge 合同明确：根事件只表示事件图中没有父事件，不表示它是参与实体上的第一个事件；独立根事件可以晚于同一实体上的其他事件，因状态变化而取消其派生候选也是合法的未发生结果。LLM Judge 和语义矫正器都不能覆盖确定性失败，也不能证明统计真实性。

输出按用途拆分为：

- `manifest.json`：版本、随机种子、配置和真实性边界；
- `domain_catalog.json`：开放类型目录与机制目录；
- `temporal_model_registry.json`：时间模型公式、参数和参数状态；
- `contexts.jsonl`、`entities.jsonl`、`context_relations.jsonl`：可复用的领域上下文；
- `episodes.jsonl`：样本窗口、场景族和各表计数；
- `events.jsonl`：发生、观测、记录时间与参与实体；
- `event_relations.jsonl`：实际事件父子关系、锚点、Δt 和机制证据；
- `candidates.jsonl`：发生、取消、替代或右删失的完整候选生命周期；
- `risk_sets.jsonl`：每次事件发生前的候选集合、风险/生存量、时间—类型—实体联合分解、调度模式和父事件归因；
- `judge_results.jsonl`：每次生成尝试的 Judge 结果、显式模型、协议重试、拒绝原因和被标记记录 ID；
- `semantic_corrections.jsonl`：每轮文本矫正的 Judge 反馈、修改句子、模型、协议重试以及修改前后文本哈希；
- `episode_texts.jsonl`：由结构化真值确定性投影的文本，每句话绑定事件/关系 ID、证据字段、文本谓词及其明确声称的关系类别；
- `validation.jsonl`、`quality_report.json`：逐样本与整批确定性检查；质量报告同时给出事件数精确直方图和可配置的空/短/中/长分层，这些边界只用于报告，不改变生成规律或质量门。

## 后续领域接入标准

新领域应提供实体类型、上下文关系、事件类型、候选机制、时间模型配置、观测模型、领域验证和文本表达。新增领域不应修改通用调度器。

当前代码只完成“结构与生成层”。后续拟合真实参数时，应在领域包中替换带 `prior` 标识的模型配置，并增加参考集拟合、留出集检验、分层分布比较和领域专家审查；不能仅凭语义 Judge 宣称统计真实。
